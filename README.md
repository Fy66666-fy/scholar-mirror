# 文献镜像 ScholarMirror

一个在本地跑的文献工作台，面向需要读一批论文、然后写点东西的人。

检索、摘要、查重、归类、找空白、推荐、项目管理都放在一个界面里，数据存在本机的一个 SQLite
文件里。默认不调用大模型，摘要都是从原文里抽出来的句子；需要更连贯的中文段落时，可以自己接
一个 OpenAI 兼容接口。

状态：开发中，版本号未定。功能能用，但边界很清楚，建议先读「它不做什么」。

---

## 现在能做什么

**找文献。** 同时查 OpenAlex、Crossref、arXiv、PubMed、Europe PMC、Semantic Scholar，
外加中科院的 ChinaXiv。重复条目会合并成一条，并记下来自哪几个源。中文模式给 PubMed 和
Europe PMC 加语言过滤，并启用 ChinaXiv。

**读摘要。** 按学科模板把摘要拆成六栏：研究问题、方法与设计、数据与样本、主要发现、
结论与意义、局限与展望。每栏都是原文原句，带句序号，可以点回去核对。抽不到的栏写
「摘要未提及」，不会补一句看起来合理的话。另有中英逐句对照，机翻，用来对术语。

**查重。** 三层：同一篇在多个源重复（自动合并）、同一项工作的不同版本（预印本与正式版）、
你粘一段稿子和已有文献的重合度（逐句比对，给重复率和出处）。第三层的语料可以扩到全文：
在摘要工坊给文献传过 PDF 之后，查重中心勾上「使用全文」，命中会标出「全文 · 方法」这样的位置。

**看关系。** 两篇之间的关联度由四路信号合成：摘要主题、概念标签、引用关系、发表信息。
每条边都能拆开看是哪一项在起作用。跨方向的桥梁文献通常是综述或方法迁移工作，值得先读。

**归类。** 自动切成若干研究方向，用区别于全局的词命名；每个方向按影响力、新近度、相关度、
完整度、可获得性五项打分，挑出值得先读的几篇。分数分开显示，不认可排序时知道该改哪一项。

**找空白。** 从样本量、随访时长、单/多中心、对照设置、效应量报告、可复现性等可核对的信号里
找缺口，每条附命中文献和原句。文献少于 4 篇时只记录观察，不下结论。

**推荐。** 先写清楚你在做什么（方向、关键词、种子文献），系统按这些召回，五路打分后做多样性
筛选。每条推荐给出理由，权重可以现场调。

**管理。** 书架、标签、阅读状态、笔记与摘录；研究项目带文献角色和里程碑；活动记录自动留在
首页。支持 BibTeX / RIS / JSON 导入导出。

---

## 它不做什么

- 不生成论文内容。摘要栏里没有的，就是原文没写。
- 不做全文分析。目前只看标题和摘要，所以「正文里做了但摘要没提」的研究会被归到「报告缺失」，
  不是「研究缺陷」。全文解析还没做。
- 不评价单篇质量。缺口分析说的是这批文献在哪些维度上同质或缺失。
- 不裁定结论冲突。方向不一致时只列可能原因（人群、剂量、终点、随访），谁对谁错要回原文。
- 全文查重需要你自己上传 PDF。库里没有的文献，语料仍然只有标题和摘要。
- 没有知网、万方的检索接口。这两家没有开放 API，只能用它们导出的文件走导入通道。

## 跑起来

```bash
pip install -r requirements.txt
streamlit run app.py
```

Windows 双击 `启动.bat`，默认端口 8601。

想先看看长什么样，访问 `http://localhost:8601/?demo=full`。会写入一套演示数据（12 篇跨学科
文献、2 个研究方向、1 个带里程碑的项目），书架名叫「演示数据」，随时可删。

## 数据源

| 源 | 覆盖 | 备注 |
|---|---|---|
| OpenAlex | 全学科 2.5 亿+ | 摘要、主题标签、参考文献 |
| Crossref | 全学科正式出版物 | 元数据权威，摘要缺失较多 |
| arXiv | 预印本 | 3 秒/次限速，官方要求 |
| PubMed | 生物医学 | MeSH 主题词、结构化摘要 |
| Europe PMC | 生命科学 | 开放全文标记、参考文献 |
| Semantic Scholar | 全学科 | TLDR 摘要，匿名配额紧，常失败 |
| ChinaXiv | 中文预印本 | 中科院平台；库不大，多词查询会自动退到单词 |

全部免注册。任一源失败不影响其余结果，检索页会显示每个源的条数和耗时。

请求层有磁盘缓存（检索 10 分钟、单篇元数据 24 小时、翻译 7 天）、退避重试和按域名限速。

## 模型与翻译（可选）

默认全本地，不联网调用模型。想用模型的话，在「设置 → 模型与翻译」里填 Base URL、模型名、
API Key，支持任意 OpenAI 兼容接口。

配好之后多三个能力：把六栏原句串成一段中文（深度总结）、质量更好的翻译、对缺口做一次复核。
Key 存在本机 `data/mirror.db`，不进导出、不写日志。用了第三方接口，摘要文本会发给那家服务商，
这一点自己判断。

翻译默认走 MyMemory 免费接口，按句翻、7 天缓存，可以在设置里切成 LLM 或关掉。机翻只适合对
术语，不能当译文用。

## 推荐怎么算

按推荐系统的常规漏斗做：召回 → 粗排 → 精排 → 重排。

**召回五路**，每路负责一种意图，并行跑：

| 通道 | 召回什么 | 靠什么 |
|---|---|---|
| 画像内容 | 方向关键词能匹配到的 | 多源检索 |
| 种子近邻 | 和你标为代表作的那几篇像的 | 标题词检索 |
| 引用脉络 | 引用了你种子文献的工作 | OpenAlex 前向引用 |
| 近期热点 | 该方向近两年被引增长快的 | OpenAlex 按被引排序 |
| 探索 | 相关性不高但质量不差的 | 从其余通道里重标 |

**精排八维**，缺信号的项不参与加权：

| 特征 | 先验权重 | 说明 |
|---|---|---|
| 相关度 | 0.26 | 关键词命中率 60% + 摘要余弦 40% |
| 库内邻近 | 0.14 | 和库里已有文献的接近程度 |
| 种子邻近 | 0.10 | 和种子文献的接近程度 |
| 引用脉络 | 0.12 | 引用种子 / 被种子引用 / 共享参考文献 |
| 引用速度 | 0.10 | 被引次数 ÷ 年龄 |
| 时效性 | 0.10 | 半衰期 5 年 |
| 新颖度 | 0.10 | 1 − 与库内最近文献的相似度 |
| 可获得性 | 0.08 | 有 PDF / OA / 都没有 |

**重排**三件事：MMR 去同质（λ=0.72）、单通道配额（不超过一半）、探索位（至少一条）。

**反馈校准**：点「设为待读」记正样本，点「不感兴趣」记负样本，写进 `rec_events`。
攒够 12 条且正负都有之后，用逻辑回归重拟合权重，再和先验各取一半（防止小样本过拟合）。
界面上会显示「默认先验」还是「已用 N 次反馈校准」。

**和待读、收藏的关系**：推荐只产出候选，点「设为待读」才进队列；队列是短期的，
读完就消失；文献库是长期资产。三者分开，推荐失败不会污染你的库。

相关度不只用余弦，是因为画像只有几个词、摘要有几百个词，纯余弦会把好文章压到 0.05 以下，
结果被高被引但跑题的论文挤到前面。这个坑是实测出来的。

## 其他算法

摘要抽取的顺序：结构化小标题 → 线索词 × 句位置 × 数字密度做全局贪心分配 → 按位置区间推断
（界面标「位置推断」）→ 仍无则留空。

查重三层分别用 DOI/PMID/arXiv 精确匹配、标题分块加词集 Jaccard、句子级最佳匹配。近似重复的
分数由四个信号加权，缺摘要时重新归一化权重。

关联图谱的阈值取两两分数的分位数，不用固定值，因为同一主题的分数分布和跨学科混检差一个量级。
布局是自己实现的 Fruchterman–Reingold，固定随机种子，同一份数据每次位置一致。

## 和 med-lit-system 的关系

那套系统只做医学，摘要与原文定位、多源并发、请求层都是它先跑通的。这一套把学科模板抽成可
插拔层，补了查重、图谱、聚类、缺口、画像与推荐、项目与笔记。两边互不依赖，可以同时装。
